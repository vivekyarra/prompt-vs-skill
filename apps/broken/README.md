# Broken integrations

Each broken app is `apps/reference/<stack>` plus exactly one targeted patch, generated by `make_broken.py`
(patches are small functions, one per Bn).

```
python apps/broken/make_broken.py --all                 # -> apps/broken/_generated/<stack>/Bn  (gitignored)
python apps/broken/make_broken.py --stack node --id B3  # a single one
```

Generated copies contain no `node_modules`/`dist`; the grader installs dependencies itself.

| ID | The single mistake | Grader check that must fail |
|---|---|---|
| B1 | Syntax error appended to the app source (app fails to start/build) | C1 (App runs) |
| B2 | Flag read with `getValue` / `getFeatureValue` / `get_feature_value` instead of the experiment method, so no exposure is recorded | C2 (Exposure sent) |
| B3 | `join_clicked` sent on page load instead of on click | C3 (Conversion on action) |
| B4 | `join_clicked` sent with identifier `other-<visitor id>`, not the exposure identity | C4 (Identity match) |
| B5 | New random identity on every load (React: random id never stored; server: `vid` cookie ignored) | C5 (Identity stable) |
| B6 | Flag is read (exposure sent) but button text stays the hard-coded control text | C6 (Flag drives the UI) |
| B7 | Server-side key embedded in a browser-loaded asset (React: in the JS bundle; server: inline `<script>` in the page). Uses `FLAGSMITH_SERVER_KEY` (React: `VITE_FLAGSMITH_SERVER_KEY` at build time) or the placeholder `ser.DEMO_LEAKED_SERVER_KEY` | C7 (diagnostic only) |

Every other check should still pass for a given Bn (each has exactly one mistake), except where an earlier failure
makes later ones moot (B1: the app never runs).
